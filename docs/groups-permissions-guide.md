# กลุ่มงาน สิทธิ์ และการลงเวลา

## เริ่มใช้งาน
1. เปิด `/admin-login` แล้วใช้บัญชีเริ่มต้น `superadmin` รหัสอยู่ใน `.super-admin-bootstrap.local.json` บนเครื่องนี้ (ไฟล์ไม่เข้า Git) เปลี่ยนผ่านเมนูข้อมูลส่วนตัวโดยใส่รหัสเดิมและยืนยันรหัสใหม่
2. `/admin/groups`: สร้างกลุ่ม กำหนดวันอนุญาต ค่าเริ่มต้นวันทำงาน/สัปดาห์ เพิ่มสมาชิก และเลือกกลุ่มหลักต่อคน ปรับจำนวนวันเฉพาะสมาชิกได้ สมาชิกอยู่หลายกลุ่มได้
3. `/admin/workforce`: เพิ่มสถานที่ วางลิงก์ Google Maps เพื่อลองอ่านชื่อและพิกัด ตรวจสอบก่อนบันทึก เลือกกลุ่มที่มองเห็นสถานที่ และกำหนดรัศมีเป็นเมตร 0–1,000,000 เมตร (1,000 เมตร = 1 กม.) ลิงก์บางแบบมีเพียงจุดกลางแผนที่/ไม่มีชื่อ ต้องตรวจหรือกรอกเอง
4. `/admin/permissions`: สร้างบทบาทแล้วเลือกสิทธิ์ มอบหมายได้หลายบทบาท ระบบตรวจทั้งเมนู ปุ่ม และ API ห้ามมอบสิทธิ์มากกว่าที่ตัวเองมี บทบาทเริ่มต้นคงไว้ บัญชี Super Admin ไม่ถูกแก้/ลบ/ลดสิทธิ์ผ่านหน้าจัดการ
5. `/admin/users`: ดาวน์โหลด Template ใหม่ทุกครั้งเพื่อได้ dropdown ปัจจุบัน กรอกแถว 6 เป็นต้นไป ตรวจไฟล์ก่อนยืนยัน รองรับ .xlsx ไม่เกิน 3 MB/1,000 คนต่อครั้ง รหัสพนักงานห้ามซ้ำ ไม่แก้ทับคนเดิม บันทึกโควต้าลาพักร้อนและวันทำงานต่อสัปดาห์ได้ ตั้ง Username/Password หลังนำเข้า

## ขาดงานรายสัปดาห์
`/admin/absence` ใช้กลุ่มหลัก สัปดาห์จันทร์–อาทิตย์ นับวันเข้าอย่างน้อยหนึ่งครั้งและวันลาที่อนุมัติ โดยไม่ซ้ำวันเดียวกัน เทียบจำนวนวันต่อคน/ค่าเริ่มต้นกลุ่ม วันหยุดบริษัทในวันอนุญาตลดจำนวนวันที่ต้องทำงาน สัปดาห์ยังไม่จบหรือเริ่มงาน/เริ่มกลุ่มกลางสัปดาห์ไม่ตัดสินขาดงาน ไม่มีกลุ่มหลักแสดงว่ายังไม่ตั้งค่า การเปลี่ยนกลุ่ม/จำนวนวันเป็นการตั้งค่าปัจจุบัน ยังไม่มีประวัติกฎรายช่วงเวลา จึงควรส่งออกรายงานก่อนเปลี่ยนกฎย้อนหลัง

## พนักงานและ GPS
หน้าแรกแสดงลงเวลาด้านบน รวมการลาเป็นเมนูเดียว `/check-in` เข้างาน → เช็คอินระหว่างวันได้หลายครั้ง → ออกงาน เมื่อออกแล้วเช็คอินเพิ่มไม่ได้

ถ้าเปิดรูปยืนยัน ใช้กล้องสดผ่าน getUserMedia ไม่มีเลือกไฟล์จากอัลบั้ม กล้องต้องใช้ HTTPS หรือ localhost และได้รับอนุญาตจากผู้ใช้ ปิดการถ่ายรูปจากหลังบ้านแล้วส่วนกล้องหายทั้งหมด

ก่อนบันทึกขอพิกัดใหม่ enableHighAccuracy/maximumAge=0 API ตรวจอายุไม่เกิน 120 วินาทีและความคลาดเคลื่อนไม่เกิน 200 เมตร ฐานข้อมูลตรวจสิทธิ์สถานที่และรัศมีอีกครั้ง สิ่งเหล่านี้ลดตำแหน่งเก่า/ไม่แม่นยำ แต่ข้อมูล GPS/ภาพที่เว็บส่งมาไม่พิสูจน์ว่าไม่ถูกปลอม ต้องทดสอบกล้องและ GPS บน iPhone/Android จริง และพิจารณา native app/device attestation หากต้องการตรวจ mock location เพิ่ม

## ฐานข้อมูลและตรวจสอบ
โปรเจกต์ปัจจุบันติดตั้ง migration 005–010 แล้ว สร้างโปรเจกต์ใหม่ใช้ `supabase/setup/new-project.sql` ซึ่งรวมทุก migration ไม่ควรรัน migration 005 ซ้ำบนฐานเดิมเพื่อหลีกเลี่ยง seed บทบาทเริ่มต้นซ้ำ

ตรวจ: `node scripts/test-group-rules.cjs`, `node --env-file=.env.local scripts/test-live-modules.mjs`, `npx tsc --noEmit`, `npm run build` และ PostgreSQL sandbox `scripts/test-module-database.cjs` (ตั้ง AUTH_TEST_PGLITE เป็นตำแหน่ง package)

ทดสอบ API จริงใช้พนักงาน/กลุ่ม/บทบาท/สถานที่ชั่วคราว แล้วลบเฉพาะรหัสที่สร้าง ตรวจสิทธิ์เกินตัว, Super Admin, ถอนการมองเห็นสถานที่, GPS เก่า/ไม่แม่นยำ/นอกรัศมี, เช็คอิน 2 ครั้ง, ออกงาน, dropdown/template/import/โควต้าลา, รหัสซ้ำ และ export ลงเวลา

พัฒนาใช้ `npm run dev` เพื่อ Fast Refresh; dev ไม่ลงทะเบียน service worker และล้างเฉพาะ cache ของแอปนี้ ไม่ควรใช้ `npm run start` ระหว่างแก้ UI


หน้ารายการสถานที่อยู่ที่ /admin/workforce มีปุ่มเพิ่ม แก้ไข และลบ ฟอร์มอยู่ที่ /admin/workforce/create เลือกกลุ่มจาก dropdown เดียวแล้วแสดงกลุ่มด้านล่าง ทุกการเปลี่ยนยังไม่บันทึกจนกดบันทึกสถานที่และการตั้งค่า การถ่ายรูปเป็นนโยบายทุกสถานที่ การลบเป็นการนำออกจากการใช้งานโดยเก็บประวัติเดิมไว้


กลุ่มงาน: หน้ารายการ /admin/groups, หน้าเพิ่ม /admin/groups/create, หน้าแก้ไข /admin/groups/edit?id=... เลือกสมาชิกได้หลายคนและเลือกทั้งหมดที่แสดง ค้นหาแล้วเลือกเพิ่มได้โดยไม่ล้างคนที่เลือกไว้นอกผลค้นหา กำหนดวันเฉพาะคนเป็นค่าทับค่าเริ่มต้นกลุ่ม หรือเลือกตามกลุ่ม แล้วบันทึกกลุ่มและสมาชิกพร้อมกันครั้งเดียว

ตารางเดิมย้ายไป /admin/groups/schedules พร้อมหน้าเพิ่ม/แก้ไขแยก ใช้เฉพาะค่ารองวันทำงานในรายงานลงเวลาเมื่อไม่มีกลุ่มหลักที่เปิดใช้งาน รายงานขาดงานแบบใหม่ไม่ใช้ตารางเดิม

Permission: หน้ารายการ /admin/permissions, หน้าเพิ่ม /admin/permissions/create, หน้าแก้ไข /admin/permissions/edit?id=... และหน้ามอบหมายบทบาท /admin/permissions/assign บทบาทระบบยังคงดูได้อย่างเดียว

Dev server ใช้ .next-dev แยกจาก .next ของ Build เพื่อไม่ให้ไฟล์ที่สร้างมาชนกัน Fast Refresh ยังทำงานตามเดิม
